# ArmoProx

ابزاری برای گرفتن یک ساب‌لینک VPN، استخراج کانفیگ‌های `vmess` / `vless` / `trojan` / `ss` از داخلش،
و سرو کردن دوباره‌ی همان کانفیگ‌ها از پشت یک آدرس تازه‌ی اختصاصی (UUID).

## ساختار پروژه

```
armoprox/
├── server.js          # بک‌اند Express: دریافت لینک اصلی، دیکد، ذخیره، سرو مجدد
├── data.json          # دیتابیس ساده‌ی فایلی (خودکار ساخته می‌شود)
├── package.json
└── public/
    ├── index.html     # رابط کاربری
    ├── css/style.css  # تم تیره‌ی نئونی + شیشه‌ای
    └── js/app.js       # منطق فرانت‌اند (فرم، QR، تاریخچه، پین)
```

## چرا بک‌اند لازم است؟

دو بخش از کار را نمی‌شود فقط با جاوااسکریپت سمت مرورگر انجام داد:

1. **گرفتن محتوای ساب‌لینک اصلی** — به‌خاطر محدودیت CORS بیشتر سرورهای ساب‌لینک، مرورگر
   اجازه‌ی fetch مستقیم را نمی‌دهد. سرور ArmoProx این کار را نیابتاً انجام می‌دهد.
2. **سرو کردن آدرس جدید** — اپ‌های VPN (v2rayN، NekoBox، Shadowrocket و…) باید بتوانند به
   آدرس جدید HTTP request بزنند و متن base64 بگیرند؛ این فقط با یک سرور واقعی ممکن است،
   نه یک صفحه‌ی باز در مرورگر شما.

به همین دلیل، این پروژه یک اپ کامل Node.js/Express است، نه فقط یک فایل HTML.

## اجرا روی سیستم خودتان

```bash
npm install
npm start
```

سپس مرورگر را باز کنید: `http://localhost:3000`

## دیپلوی روی یک سرور واقعی

برای این‌که آدرس تازه‌ی ساخته‌شده از خارج هم در دسترس باشد (تا اپ‌های VPN بتوانند سابسکرایب
کنند)، باید این پروژه را روی یک هاست عمومی با دامنه/IP ثابت اجرا کنید؛ مثلاً:

- یک VPS ساده (`pm2 start server.js` یا با `systemd`/`docker`)
- سرویس‌هایی مثل Render، Railway یا Fly.io که Node app را مستقیم اجرا می‌کنند

پشت یک HTTPS واقعی (با Nginx + Let's Encrypt یا سرویس‌های بالا) بگذارید تا آدرس‌های
تولیدشده `https://` باشند.

## نکات مهم درباره‌ی پین شش‌رقمی

پین در این نسخه فقط برای **محافظت از نمایش دوباره‌ی لینک/QR داخل خودِ اپ ArmoProx** است:
هش پین (SHA-256) در `localStorage` مرورگر کاربر ذخیره می‌شود، نه روی سرور.

آدرس `/sub/:id` که به اپ‌های VPN داده می‌شود **عمداً بدون پین** باز می‌ماند، چون اپ‌های VPN
راهی برای وارد کردن پین ندارند و باید بتوانند مستقیم سابسکرایب کنند. پس:

- پین از تاریخچه‌ی محلی شما در برابر افراد دیگری که به همین مرورگر/دستگاه دسترسی دارند محافظت می‌کند.
- پین جلوی دسترسی به خودِ لینک (اگر کسی آدرس را جایی ببیند) را نمی‌گیرد. اگر می‌خواهید این
  سطح از امنیت را هم داشته باشید، باید احراز هویت واقعی (توکن/رمز عبور سمت سرور) اضافه کنید —
  که در معماری فعلی جای گسترشش در `server.js` داخل روت `/sub/:id` است.

## قابلیت‌های پیاده‌سازی‌شده

- فرم ورودی ساب‌لینک + پین شش‌رقمی + عنوان اختیاری
- فچ سرور-ساید لینک اصلی، دیکد Base64 (یا تشخیص متن ساده)، اعتبارسنجی خطوط `vmess/vless/trojan/ss`
- تولید UUID و آدرس جدید از طریق `/sub/:id`
- نمایش QR Code (کتابخانه‌ی `qrcode`)، دانلود QR به‌صورت PNG
- کپی لینک با یک کلیک
- تاریخچه‌ی محلی (`localStorage`) با قفل پین برای مشاهده‌ی دوباره و امکان حذف هر مورد
- پیام‌های خطای فارسی و کاربرپسند برای لینک نامعتبر، عدم دسترسی به سرور مبدا، یا نبود کانفیگ معتبر
- تم تیره‌ی نئونی شیشه‌ای، کاملاً راست‌چین و ریسپانسیو

## توسعه‌ی بیشتر (پیشنهادها)

- افزودن دیتابیس واقعی (SQLite/Postgres) به‌جای `data.json` برای مقیاس بزرگ‌تر

- افزودن Rate limiting روی `/api/generate` برای جلوگیری از سوءاستفاده
- افزودن گزینه‌ی به‌روزرسانی خودکار (sync دوره‌ای از لینک مبدا)
